# TacXense RLT 采集规程

RLT phase two 的方法规格（采集流程、MLP 表示与结构、replay transition、replay 规模与更新节奏）见
[rlt-spec.md](rlt-spec.md)。本文只记任务级的采集规程。

## insert-ethernet 的采集规程（2026-09-22 用户决定）

[rlt-spec.md](rlt-spec.md) 第 1 节的状态图规定**机制**：按 b 怎么开窗、介入怎么判定、anchor 怎么取。这一节规定**在任务的哪个
位置用它**，属于任务级实验设计，换任务要重新定。以下两条在下一轮重跑时生效，都不需要改代码。

### 关键阶段从"还在空中"开始，不从接触开始

以前是撞上去之后才开窗。改为网口还在空中、尚未接触插座时就按 b 进入关键阶段。

理由是要让 actor 有机会学会一个具体的失败模式恢复：**空中对位不准 → 插一次没进去 → 抬起来重新
对位 → 再插**。如果窗口从接触才开始，这段对位过程全部落在关键阶段之外，replay 里根本没有它，
actor 既看不到失败发生前的状态，也学不到纠正动作。窗口提前意味着一段关键阶段会包含一次或多次
失败尝试加上恢复，这正是希望 actor 接管的部分。

代价要知道：关键阶段变长，[rlt-spec.md](rlt-spec.md) 第 5 节的 `N_transition/episode = floor((L-C)/s)+1`
直接随 `L` 增长，所以同样的 `warm_up=600` 现在对应更少的 episode；标签后的特征物化也随之变长
（已批量化，见 plan.md 对应事务，真机时长待测）。

### 介入手法：插不进去就抬起来重新定位，不要顶着侧壁

人工接管时，一次插入没成功**必须抬起来重新对位**，不能顶着插座侧壁继续往里怼。

用户的现场观察是：卡在插入界面的侧面时摩擦力大、自主调整空间太小，target 和 state 容易不一致。

机制上这与相对 state 的动作表示相互作用（代码分析，非现场测量）：动作的前 18 维是**相对当前
`state_raw` 的 delta**，codec 解码时把当前实测 state 加回去才得到下发的绝对目标。手臂被侧壁顶住
时 state 不再跟随指令，于是每一条新指令都锚在"卡住的那个位置"附近 —— 策略想往前推，但可推的量
被自己的锚点吃掉了。叠加 Cartesian 阻抗（`stiffness_ratio: 0.2`）和 tacxense `architecture.md` § 4.45"采样动作块原样下发、
不做执行门控"，这种姿态下既压不进去也纠正不回来，采到的 transition 只是一段 target 与 state 持续
背离的数据，对 actor 没有学习价值，反而会把"顶住不动"这个行为写进 replay。

抬起来重新定位则让 state 重新跟上 target，恢复动作本身也是希望 actor 学会的那个行为。
